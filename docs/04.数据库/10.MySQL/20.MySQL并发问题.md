## MySQL脏读、幻读、不可重复读问题

### 建测试表和数据

```sql
create table show_me_problem
(
	id int auto_increment,
	price int null,
	location varchar(256) null,
	constraint show_me_problem_pk
		primary key (id)
) engine = InnoDB
comment 'mysql并发问题演示表';

insert into show_me_problem values (1,1,'第一条');
insert into show_me_problem values (2,2,'第二条');
insert into show_me_problem values (3,3,'第三条');
```

> 我的mysql版本是：8.0.27

下面保留原来的实验截图，SQL 和解释已经校正。使用两个独立数据库连接，按文中的交替顺序执行，不要一次运行完整脚本。每轮结束后提交或回滚两个连接的事务；再次运行案例前，确保演示数据恢复到初始状态。

### 回顾隔离级别和并发问题

四种隔离级别：

- 读未提交：最低的隔离级别，会产生脏读、幻读、不可重复读问题。
- 读已提交：解决脏读问题，仍会产生幻读、不可重复读问题。
- 可重复读：InnoDB 默认隔离级别。普通快照读复用事务内首次一致性读建立的视图；锁定范围读取通常通过临键锁防止范围内插入。不能笼统说 InnoDB 的 RR 一定产生幻读。
- 串行化：提供更强隔离，显式事务中的普通查询可能转换为共享锁定读，等待和冲突也可能增加；并不意味着所有操作都禁止并发。

三种问题描述：

- 脏读：指的是事务A，B交替进行，A在事务进行中读到了B未提交的数据。
- 幻读：同一事务重复执行相同条件的范围查询，因其他事务提交插入或删除，符合条件的行集合发生变化。
- 不可重复读：同一事务重复读取已有记录，因其他事务提交修改，读到了不同的值。

这些现象与隔离级别、读取方式有关，原理见 [MySQL 事务与 MVCC](/pages/mysql-mvcc/)。

### 真正的幻读：范围查询的结果集合改变

使用读已提交隔离级别演示。此轮开始时，表中只有初始化的 `id = 1、2、3`。

第一步，A 查询范围内的记录：

```sql
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
SELECT id, price, location FROM show_me_problem WHERE id BETWEEN 1 AND 4;
-- 返回 1、2、3，事务暂不结束
```

第二步，B 插入范围内的新记录并提交：

```sql
START TRANSACTION;
INSERT INTO show_me_problem VALUES (4, 4, '第四条');
COMMIT;
```

第三步，A 重复执行相同查询：

```sql
SELECT id, price, location FROM show_me_problem WHERE id BETWEEN 1 AND 4;
-- 返回 1、2、3、4，出现新的匹配行
COMMIT;
```

A 在同一事务中看到范围结果多了一行，这才是这里要演示的幻读。A、B 都结束事务后，在自动提交模式下执行 `DELETE FROM show_me_problem WHERE id = 4;`，恢复下一节需要的数据状态。

### RR 中查不到，却插入失败

下面的原截图演示另一种现象：两次普通查询结果没有变化，但插入遇到主键冲突。应当用快照读与唯一键检查的差异解释，不能直接当成两次范围查询产生幻读的证据。

   ![6](https://img.superkusch.fun/docs/6.png)

1. 切换**可重复读隔离级别**，并且分别开启事务。

   ```sql
   set transaction isolation level repeatable read ;
   start transaction;
   ```

2. 先由 A 通过普通查询建立快照，再由 B 插入并提交：

  1. A窗口 查询 id=4 的数据是否存在了。此时应该是没有的。A事务进行中

     ![7](https://img.superkusch.fun/docs/7.png)


2. B窗口 插入一条id=4 的数据，**并且提交事务**。此时B窗口查询数据是可以查询id=4的数据是可以查询到的。

3. A窗口 再次进行查询确认是否有 id=4 数据了，查询出来还是不存在，此时A执行插入语句，但是会失败！

> 附上：
>
> A窗口语句：
>
> ```sql
> -- 可重复读
> set transaction isolation level repeatable read ;
> start transaction;
> 
> select id, price, location
> from show_me_problem
> where id = 4;
>
> -- B 插入并提交后，再运行同一 SELECT，仍返回空结果
> select id, price, location from show_me_problem where id = 4;
> -- 唯一键检查发现数据库中已存在 id=4，以下语句报重复主键错误
> insert into show_me_problem values (4,1,'第四条');
> 
> rollback;
> ```
>
> B窗口语句
>
> ```sql
> -- 可重复读
> set transaction isolation level repeatable read ;
> start transaction;
> 
> insert into show_me_problem values (4,1,'第四条');
> 
> commit;
> ```

普通查询复用了旧视图，唯一键检查却必须维护当前数据的唯一性。如果业务需要保护“检查后再操作”的范围，应设计合适的事务和锁定读；具体机制见 [MySQL 锁机制](/pages/mysql-locks/)。

### 不可重复读

开始前，确认两个连接都没有未结束的事务，并在自动提交模式下执行 `UPDATE show_me_problem SET price = 1 WHERE id = 1;`。本轮让 A 先查询，再让 B 更新并提交，最后让 A 再查一次。

   ![8](https://img.superkusch.fun/docs/8.png)

1. 切换 **读已提交隔离级别**，并且分别开启事务。

   ```sql
   set transaction isolation level read committed ;
   start transaction;
   ```

2. 执行左边窗口的查询，结果如下：

   ![9](https://img.superkusch.fun/docs/9.png)



3. 此时执行右侧更新语句，同时提交事务。此时状态是右侧执行了，并且提交了，左侧还在进行中，还未提交。

4. 左侧窗口再次执行查询语句，结果如下：

   ![10](https://img.superkusch.fun/docs/10.png)

5. 可见，在同一个事务中，两次相同查询，竟然查询出不同结果，这就是不可重复读问题。

> 附上：
>
> A窗口语句：
>
> ```sql
> -- 读已提交
> set transaction isolation level read committed ;
> start transaction;
> 
> select id, price, location
> from show_me_problem
> where id =1;
>
> -- B 提交后执行第二次读取，从 1 变为 333
> select id, price, location from show_me_problem where id = 1;
> rollback;
> ```
>
> B窗口语句
>
> ```sql
> -- 读已提交
> set transaction isolation level read committed ;
> start transaction;
> 
> update show_me_problem set price=333 where id = 1;
> 
> commit;
> ```
