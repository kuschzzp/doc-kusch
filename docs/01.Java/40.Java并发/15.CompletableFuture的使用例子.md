# CompletableFuture

首页需要汇总客户数、订单数和积分排名时，互不依赖的查询可以并行提交，最后合并结果。总耗时有机会接近最慢的查询，但也取决于线程池、数据库连接池和下游承载能力，不能直接用线程数推算加速比。

`FutureTask` 可以承载异步任务，但需要交给线程或执行器才会执行。`CompletableFuture` 的主要便利是声明任务依赖、组合结果和处理异常；它的 `get()`、`join()` 在结果尚未完成时仍会阻塞调用线程。

## 先看 FutureTask

下面用两个耗时不同的任务模拟查询，代码可在 Java 8 运行，保存为 `FutureTaskDemo.java`：

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.FutureTask;
import java.util.concurrent.TimeUnit;

public class FutureTaskDemo {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);
        try {
            FutureTask<String> one = new FutureTask<>(() -> {
                Thread.sleep(300);
                return "客户数：100";
            });
            FutureTask<String> two = new FutureTask<>(() -> {
                Thread.sleep(500);
                return "订单数：200";
            });
            pool.execute(one);
            pool.execute(two);
            System.out.println(one.get(2, TimeUnit.SECONDS));
            System.out.println(two.get(2, TimeUnit.SECONDS));
        } finally {
            pool.shutdown();
            try {
                if (!pool.awaitTermination(3, TimeUnit.SECONDS)) {
                    pool.shutdownNow();
                }
            } catch (InterruptedException e) {
                pool.shutdownNow();
                Thread.currentThread().interrupt();
                throw e;
            }
        }
    }
}
```

两个任务都先提交，再获取结果，因此在 `one.get()` 等待期间，第二个任务也可以执行。异步提交与最终等待并不矛盾，关键是在哪里等待，以及是否还有其他工作可以并行推进。

## 用 CompletableFuture 组合任务

`supplyAsync` 执行有返回值的任务，`runAsync` 执行无返回值的任务。不指定执行器时通常使用共享的 `ForkJoinPool.commonPool()`；数据库查询、HTTP 调用等阻塞任务建议使用有明确容量和拒绝策略的业务线程池。

| 方法 | 用途 | 结果类型示例 |
| --- | --- | --- |
| `thenApply` | 同步转换上一步的结果 | `Future<User> → Future<String>` |
| `thenCompose` | 上一步完成后启动另一个异步步骤，并展开嵌套结果 | `Future<User> → Future<Orders>` |
| `thenCombine` | 合并两个任务的结果 | 两个 Future 合成一个 |
| `allOf` | 在全部给定任务结束后完成，本身不收集结果 | `CompletableFuture<Void>` |

表中的 `Future<T>` 是简写，实际使用的是 `CompletableFuture<T>`。例如异步查出用户后再异步查订单，应该用 `thenCompose`；如果用 `thenApply` 返回一个 Future，就会得到嵌套的 `CompletableFuture<CompletableFuture<...>>`。

以下是完整的组合示例，保存为 `CompletableFutureDemo.java`：

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

public class CompletableFutureDemo {
    private static String query(String result, long millis) {
        try {
            Thread.sleep(millis);
            return result;
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new java.util.concurrent.CompletionException(e);
        }
    }

    public static void main(String[] args) throws Exception {
        ThreadPoolExecutor pool = new ThreadPoolExecutor(
                2, 2, 0L, TimeUnit.MILLISECONDS,
                new ArrayBlockingQueue<>(16),
                new ThreadPoolExecutor.AbortPolicy());
        try {
            CompletableFuture<String> customers = CompletableFuture
                    .supplyAsync(() -> query("100", 300), pool)
                    .thenApply(value -> "客户数：" + value);

            CompletableFuture<String> orders = CompletableFuture
                    .supplyAsync(() -> query("200", 500), pool);

            CompletableFuture<String> summary = customers.thenCombine(
                    orders, (c, o) -> c + "，订单数：" + o);

            CompletableFuture<String> detail = orders.thenCompose(
                    count -> CompletableFuture.supplyAsync(
                            () -> query("订单详情，数量：" + count, 100), pool));

            CompletableFuture<Void> ready =
                    CompletableFuture.allOf(summary, detail);
            // 这是同步程序的结果边界；此处最多等待两秒。
            ready.get(2, TimeUnit.SECONDS);
            System.out.println(summary.join());
            System.out.println(detail.join());
        } finally {
            pool.shutdown();
            try {
                if (!pool.awaitTermination(3, TimeUnit.SECONDS)) {
                    pool.shutdownNow();
                }
            } catch (InterruptedException e) {
                pool.shutdownNow();
                Thread.currentThread().interrupt();
                throw e;
            }
        }
    }
}
```

`allOf` 本身不阻塞调用者，示例中的 `get` 才会阻塞。`ready` 正常完成后，再读取已经完成的子任务结果不需要继续等待。任一子任务失败会使 `allOf` 在所有子任务完成后异常完成；它不会自动取消其他任务，也不是遇到首个失败就立即返回。

没有 `Async` 后缀的回调可能由完成上一步的线程执行，也可能由注册回调的线程执行。轻量转换适合这种形式；耗时回调可以用 `thenApplyAsync(fn, pool)` 等显式指定执行器。也不要在线程池工作线程中阻塞等待同一个已满线程池里的新任务，以免线程饥饿。

## get 和 join 都可能等待

| 方法 | 结果未完成时 | 异常与中断 |
| --- | --- | --- |
| `get()` | 阻塞等待 | 声明 `InterruptedException`、`ExecutionException` |
| `get(timeout, unit)` | 最多等待指定时长 | 额外可能抛出 `TimeoutException` |
| `join()` | 阻塞等待，无超时参数 | 失败通常包装为非受检的 `CompletionException`；不提供可中断等待接口 |

任务被取消时，读取结果还可能抛出 `CancellationException`。`get(timeout)` 超时只表示调用者停止本次等待，后台任务通常仍在执行。

Java 9 起提供 `orTimeout` 和 `completeOnTimeout`，分别让 Future 超时后异常完成或使用默认结果完成。它们同样不会自动终止已经开始的数据库查询或 HTTP 请求。需要在底层客户端设置连接、读取、查询超时；`CompletableFuture.cancel(true)` 也不能保证中断执行任务的线程。

## 异常应该如何处理

`exceptionally` 适合异常恢复；`handle` 同时接收成功值和异常并转换结果；`whenComplete` 更适合观察、记录结果，通常不改变原来的成功或失败状态。观察回调自身抛出的异常也可能使后续阶段失败。

例如积分排名允许降级，而客户数、订单数属于必需信息，可以只给排名设置明确的默认值：

```java
CompletableFuture<String> rank = CompletableFuture
        .supplyAsync(() -> loadRanking(), pool)
        .exceptionally(error -> {
            log.warn("积分排名暂不可用", error);
            return "暂不可用";
        });
```

这里的 `loadRanking`、`pool`、`log` 由业务代码提供。这个片段强调的是降级位置；不能把所有异常都转换为 0 或空列表，否则“查询失败”和“业务上没有数据”就混在一起了。异常恢复也不能解决永久不返回的任务，仍需设置超时。

## 批量任务：限制线程数与排队规模

原来按批次数创建线程池，很容易把任务数量变成线程数量。改成固定并发、有界队列，并让业务知道提交可能失败。下面的示例处理 3401 条数据，保存为 `BatchFutureDemo.java`，可在 Java 8 运行：

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.RejectedExecutionException;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

public class BatchFutureDemo {
    public static List<String> load(int maxSize) throws Exception {
        if (maxSize < 0) {
            throw new IllegalArgumentException("maxSize 不能为负数");
        }
        if (maxSize == 0) {
            return new ArrayList<>();
        }
        ThreadPoolExecutor pool = new ThreadPoolExecutor(
                4, 4, 0L, TimeUnit.MILLISECONDS,
                new ArrayBlockingQueue<>(16),
                new ThreadPoolExecutor.AbortPolicy());
        try {
            List<CompletableFuture<List<String>>> futures = new ArrayList<>();
            final int batchSize = 1000;
            for (int offset = 0; offset < maxSize;) {
                final int start = offset;
                final int end = (int) Math.min((long) start + batchSize, maxSize);
                futures.add(CompletableFuture.supplyAsync(() -> {
                    List<String> batch = new ArrayList<>();
                    for (int i = start; i < end; i++) {
                        batch.add("Data " + i);
                    }
                    return batch;
                }, pool));
                offset = end;
            }
            CompletableFuture.allOf(
                    futures.toArray(new CompletableFuture<?>[0]))
                    .get(30, TimeUnit.SECONDS);

            List<String> result = new ArrayList<>();
            for (CompletableFuture<List<String>> future : futures) {
                result.addAll(future.join());
            }
            return result;
        } catch (RejectedExecutionException e) {
            // 直接提交时就可能被拒绝，此时还拿不到对应的 Future。
            throw new IllegalStateException("批量任务超过当前处理容量", e);
        } finally {
            pool.shutdown();
            try {
                if (!pool.awaitTermination(3, TimeUnit.SECONDS)) {
                    pool.shutdownNow();
                }
            } catch (InterruptedException e) {
                pool.shutdownNow();
                Thread.currentThread().interrupt();
                throw e;
            }
        }
    }

    public static void main(String[] args) throws Exception {
        System.out.println(load(0).size());    // 0
        System.out.println(load(3401).size()); // 3401
    }
}
```

这个示例只在全部成功后返回汇总结果，也不把错误字符串混入正常数据。有界队列限制的是执行器排队任务数，不是结果集大小；大量数据还需采用分窗口提交和流式消费，避免把全部 Future、全部数据留在内存中。

`AbortPolicy` 在饱和时显式拒绝，调用方应决定返回繁忙、限流或稍后重试。不要换成静默丢弃策略，否则对应 Future 可能一直无法完成。`CallerRunsPolicy` 会让提交者执行任务，可以形成反馈压力，但也会阻塞原本期望快速返回的请求线程。

示例的线程池归方法所有，因此在 `finally` 中关闭。服务中一般复用由容器管理的线程池，在应用关闭时统一释放，不能每次请求结束就关闭共享池。`shutdownNow()` 只是尝试中断，任务必须配合响应中断，外部调用仍要设置自己的超时。

另外，Spring 常见的线程绑定事务不会自动传播到这些异步任务中。异步线程里单独开启的事务，也不会与调用线程组成一个整体事务。
