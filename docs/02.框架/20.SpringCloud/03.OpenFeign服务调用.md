# OpenFeign 服务调用

官方文档：[Spring Cloud OpenFeign](https://docs.spring.io/spring-cloud-openfeign/docs/current/reference/html/)

OpenFeign 是声明式 HTTP 客户端。

以前我们调用远程服务可能会写一堆 `RestTemplate` 代码。Feign 的思路是：把远程 HTTP 调用写成 Java 接口。

## 引入依赖

```xml
<dependency>
  <groupId>org.springframework.cloud</groupId>
  <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
```

启动类开启 Feign：

```java
@EnableFeignClients
@SpringBootApplication
public class OrderApplication {
    public static void main(String[] args) {
        SpringApplication.run(OrderApplication.class, args);
    }
}
```

## 定义 FeignClient

```java
@FeignClient(name = "user-service")
public interface UserClient {

    @GetMapping("/users/{id}")
    UserDTO getById(@PathVariable("id") Long id);
}
```

调用：

```java
@Service
public class OrderService {
    private final UserClient userClient;

    public OrderService(UserClient userClient) {
        this.userClient = userClient;
    }

    public UserDTO getOrderUser(Long userId) {
        return userClient.getById(userId);
    }
}
```

`name = "user-service"` 对应注册中心里的服务名。

如果你配置了 Nacos、Eureka、Consul 等服务发现，Feign 会结合 Spring Cloud LoadBalancer 找到具体实例。

## url 和 name 的区别

指定服务名：

```java
@FeignClient(name = "user-service")
```

适合走注册中心和负载均衡。

指定固定地址：

```java
@FeignClient(name = "user-api", url = "http://localhost:8081")
```

适合本地调试或调用固定第三方地址。

实际项目里，内部服务优先用服务名，外部系统可以用 url。

## 超时配置

Feign 底层请求一定要配超时，不要无限等。

```yaml
spring:
  cloud:
    openfeign:
      client:
        config:
          default:
            connectTimeout: 2000
            readTimeout: 5000
          user-service:
            connectTimeout: 1000
            readTimeout: 3000
```

`default` 是全局默认。

`user-service` 是针对某个 FeignClient 的配置。

## 日志配置

Java 配置：

```java
@Configuration
public class FeignConfig {
    @Bean
    Logger.Level feignLoggerLevel() {
        return Logger.Level.BASIC;
    }
}
```

配置日志级别：

```yaml
logging:
  level:
    com.example.client.UserClient: DEBUG
```

Feign 的日志级别常见有：

```text
NONE
BASIC
HEADERS
FULL
```

生产环境别轻易开 FULL，可能把请求体、响应体、敏感信息都打出来。

## fallback

OpenFeign 可以和 Spring Cloud CircuitBreaker 集成。下面的开关还需要对应的 CircuitBreaker 实现依赖，例如 `spring-cloud-starter-circuitbreaker-resilience4j`；仅声明 `fallback` 并不会自动启用熔断能力。

开启：

```yaml
spring:
  cloud:
    openfeign:
      circuitbreaker:
        enabled: true
```

定义 fallback：

```java
@FeignClient(name = "user-service", fallback = UserClientFallback.class)
public interface UserClient {
    @GetMapping("/users/{id}")
    UserDTO getById(@PathVariable("id") Long id);
}

@Component
public class UserClientFallback implements UserClient {
    @Override
    public UserDTO getById(Long id) {
        return new UserDTO(id, "unknown");
    }
}
```

fallback 不是万能兜底。它适合返回默认值、降级提示，不适合掩盖所有错误。

### 使用 Sentinel 时怎样接入

Spring Cloud Alibaba 的 Sentinel Feign 适配是另一条接入路径。以其 2023.x 文档为例，需要匹配版本的 `spring-cloud-starter-alibaba-sentinel`，并开启：

```yaml
feign:
  sentinel:
    enabled: true
```

它不等于前面的 Spring Cloud CircuitBreaker + Resilience4j 配置。选定项目实际使用的一种集成方式，再配置该实现的资源规则和指标，不要把两套开关、熔断规则混在一起。

如果降级时需要记录原因，可以使用 `fallbackFactory`。下面的接口和工厂替换前面的 `fallback` 示例：

```java
@FeignClient(name = "user-service", fallbackFactory = UserFallbackFactory.class)
public interface UserClient {
    @GetMapping("/users/{id}")
    UserDTO getById(@PathVariable("id") Long id);
}

@Component
public class UserFallbackFactory
        implements org.springframework.cloud.openfeign.FallbackFactory<UserClient> {
    private static final org.slf4j.Logger log =
            org.slf4j.LoggerFactory.getLogger(UserFallbackFactory.class);

    @Override
    public UserClient create(Throwable cause) {
        return id -> {
            log.warn("用户服务调用失败，userId={}", id, cause);
            throw new IllegalStateException("用户信息暂不可用", cause);
        };
    }
}
```

工厂既要注册为 Bean，也要在 `@FeignClient` 的 `fallbackFactory` 中关联；只写一个工厂类不会生效。不同发布线使用的接口包名可能变化，旧版示例不能直接照搬。

限流拒绝、熔断打开、网络超时和业务错误应分别观察。查询类接口可以按约定返回降级状态；创建订单、扣库存等操作不能伪造成功。回退处理也不会自动撤销下游已执行的写入，重试前仍需考虑幂等。

参考：[Spring Cloud Alibaba 2023：Sentinel 适配 OpenFeign](https://sca.aliyun.com/docs/2023/user-guide/sentinel/advanced-guide/)。

## 常见坑

### 1. 忘了 @EnableFeignClients

接口写了，Bean 没生成，启动报找不到注入对象。

### 2. PathVariable 没写 value

建议明确写：

```java
@PathVariable("id") Long id
```

不要依赖参数名推断。

### 3. 超时不配

远程服务卡住时，调用方线程也被拖住。

### 4. fallback 里又调用远程服务

fallback 应该简单、稳定。不要在 fallback 里继续做复杂远程调用。

## 小结

OpenFeign 的价值是让服务调用更像本地接口。

但它本质还是 HTTP 调用，所以要关心：

```text
服务名
超时
日志
熔断
fallback
```
