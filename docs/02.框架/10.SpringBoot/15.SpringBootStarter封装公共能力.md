# Spring Boot Starter 封装公共能力

多个服务都要接入日志、缓存客户端或统一认证时，可以用 Starter 统一依赖和默认装配。它解决的是接入方式重复的问题，公共组件仍然需要有清晰的职责边界。

本文以 Spring Boot 3.x 为例。设计目标是：引入后按条件生效，配置可覆盖，业务方提供自己的 Bean 时默认实现自动退出。

## 模块怎么分

```text
acme-client                         普通 Java 接口与实现
acme-spring-boot-autoconfigure       自动配置、配置属性
acme-spring-boot-starter             聚合依赖，方便业务方引入
```

小型组件也可以合并模块。Starter 本身不需要启动类，不应把 Web、数据库、Redis 等所有依赖无条件塞给使用方；需要某种能力时，再引入对应 Starter。

## 最小自动配置示例

假设已有 `AcmeClient` 和接收超时参数的 `DefaultAcmeClient(Duration timeout)`，先声明配置属性：

```java
package com.example.acme.autoconfigure;

import java.time.Duration;
import org.springframework.boot.context.properties.ConfigurationProperties;

@ConfigurationProperties("acme.client")
public class AcmeClientProperties {
    private Duration timeout = Duration.ofSeconds(2);

    public Duration getTimeout() {
        return timeout;
    }

    public void setTimeout(Duration timeout) {
        this.timeout = timeout;
    }
}
```

自动配置类负责按条件创建 Bean：

```java
package com.example.acme.autoconfigure;

import com.example.acme.AcmeClient;
import com.example.acme.DefaultAcmeClient;
import org.springframework.boot.autoconfigure.AutoConfiguration;
import org.springframework.boot.autoconfigure.condition.ConditionalOnClass;
import org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;

@AutoConfiguration
@ConditionalOnClass(AcmeClient.class)
@ConditionalOnProperty(prefix = "acme.client", name = "enabled",
        havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(AcmeClientProperties.class)
public class AcmeClientAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean(AcmeClient.class)
    public AcmeClient acmeClient(AcmeClientProperties properties) {
        return new DefaultAcmeClient(properties.getTimeout());
    }
}
```

随后在自动配置模块创建资源文件：

```text
src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

内容一行一个自动配置类的完整名称：

```text
com.example.acme.autoconfigure.AcmeClientAutoConfiguration
```

Boot 3.x 使用这个 imports 文件注册自动配置，不再通过旧式 `spring.factories` 的 `EnableAutoConfiguration` 键注册。自动配置类应放在独立包中，避免被业务应用的组件扫描提前加载；也不要在自动配置中用宽泛的 `@ComponentScan` 扫入业务代码。

业务方引入 Starter 后，可以修改默认值或关闭能力：

```yaml
acme:
  client:
    enabled: true
    timeout: 1500ms
```

配置属性应使用独立前缀，避免污染全局配置。需要 IDE 提示时，在构建阶段接入 `spring-boot-configuration-processor` 生成元数据；对端点、超时等关键属性增加校验，让错误尽早暴露。

## 哪些适合共享，哪些留给业务

| 适合封装 | 不宜固化在公共组件里 |
| --- | --- |
| 客户端创建、连接和超时配置 | 某个业务系统的库表、租户数据 |
| 脱敏日志、指标、链路上下文 | 无差别记录所有接口入参或 Token |
| 认证协议接入、凭证校验扩展点 | 某个系统的角色菜单和权限判断规则 |
| 缓存访问接口、序列化约定 | 所有业务共用的固定 Key 或失效策略 |

例如统一认证组件可以封装 OIDC 客户端配置和校验流程，但权限数据应由业务授权服务维护，通过明确接口或事件刷新。不要把菜单权限当成 Nacos 配置，也不要让引入 Starter 意味着自动创建业务表或修改生产权限。

登录与授权还要区分用户和应用：用户登录通常使用 OIDC 授权码流程，结合 PKCE；`client_credentials` 用于应用代表自身访问资源，不能替代用户登录。Spring Authorization Server 并不原生提供旧式密码授权模式，不应把“支持密码模式”当作开箱即用能力。

## 发布前验证什么

自动配置可以用 `ApplicationContextRunner` 验证，重点覆盖这些行为：

1. 默认配置满足条件时，客户端 Bean 能创建。
2. `enabled=false` 时，自动配置不创建客户端。
3. 业务方提供 `AcmeClient` Bean 时，默认实现退出。
4. 配置属性能绑定，非法值有明确错误。
5. 缺少可选依赖时不会误装配，兼容矩阵内的 Boot 版本能正常启动。

Starter 的升级会影响多个使用方，因此依赖版本、默认值和公共接口的变化都需要写进升级说明。先让少量服务验证，再扩大使用范围，比让所有服务同时升级更容易定位问题。
